# Google Cloud staging (one region)

A single UK staging cell on Google Cloud in **europe-west2 (London)**, holding the fictional test organisation only (ADR-0157). Production hosting is a separate decision; the AWS CDK app in `infra/` is unchanged.

## What runs where

| Piece            | Google Cloud                                                      | Notes                                                                                                                                                                   |
| ---------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Web + API        | Cloud Run service `thapsus-stg-uk-app`                            | The web container takes the traffic and proxies `/v1`, `/scim` and `/global` to the API sidecar on `127.0.0.1:4000`. The API has no address of its own. Scales to zero. |
| Worker           | Cloud Run service `thapsus-stg-uk-worker`                         | Called by Cloud Scheduler `POST /drain` every minute (OIDC, Cloud Run IAM). Not public.                                                                                 |
| Migrations, seed | Cloud Run jobs `thapsus-stg-uk-migrate`, `thapsus-stg-uk-seed`    | Both run the API image.                                                                                                                                                 |
| PostgreSQL 17    | Cloud SQL `thapsus-stg-uk-pg`, `db-g1-small`, zonal               | RLS and roles come from the migrations. Reached only through the Cloud Run connector (no authorised networks). Backups and point-in-time recovery are kept in London.   |
| Files            | Cloud Storage `<project>-thapsus-stg-uk-files`                    | Private, versioned, CMEK (`files` key), London.                                                                                                                         |
| Email            | Cloud Storage `<project>-thapsus-stg-uk-mail`                     | No email provider yet: each message is an `.eml` object, kept 14 days.                                                                                                  |
| Sensitive fields | Cloud KMS key `fields` (key ring `thapsus-stg-uk-keys`, London)   | Wraps the per-record data keys of the sensitive-data store.                                                                                                             |
| Secrets          | Secret Manager, replicated to London only                         | Generated by OpenTofu: database roles, internal token, signing key, test sign-ins.                                                                                      |
| Images           | Artifact Registry `europe-west2-docker.pkg.dev/<project>/thapsus` | Created by `bootstrap.sh`; keeps the 15 most recent versions.                                                                                                           |

Nothing is created outside europe-west2. `staging/tests/staging.tftest.hcl` checks this offline, including backups and secret replicas, and `pnpm verify` runs those tests (step `gcp`).

## First deploy (owner)

Follow `docs/HUMAN_TODO.md` §9. In short:

1. Create a project with billing, then run `bash infra/gcp/bootstrap.sh <project-id>` in Cloud Shell.
2. Add the GitHub variables that the script prints.
3. Create the `staging-gcp` environment with yourself as a required reviewer.
4. Run **Deploy staging (Google Cloud)** from the Actions tab.
5. Approve the plan when it is shown.

The first run takes about 25 minutes, most of it creating Cloud SQL.

## Every deploy

The deploy runs after CI passes on `main`, or when started by hand.

1. **Build** the web, api and worker images, tagged with the commit SHA.
2. **Plan.** The workflow posts the OpenTofu change set (resource addresses and actions, no values) in the run summary. It refuses to continue if `staging-gcp` has no required reviewers.
3. **Approve.** You approve the `staging-gcp` deployment.
4. **Deploy:**
   - re-plan, and stop if the change set differs from the approved one;
   - apply the migrate and seed jobs and their dependencies;
   - run the migrations;
   - apply the rest (app, worker, schedule), then run the seed if it has never succeeded;
   - smoke-test `/health` and `/signin`.

   Each apply uses a saved plan that must fall inside the approved change set.

## Signing in to the test organisation

```sh
gcloud secrets versions access latest --secret=thapsus-stg-uk-test-logins --project=<project-id>
```

This prints the app URL, the workspace (`kestrel`) and one email and password per role: owner, HR admin, payroll admin, manager and employee.

Admin roles must set up an authenticator app at first sign-in.

To change the passwords, bump `test_login_generation` in `staging/variables.tf` and deploy with **seed** ticked. The seed resets the test users' passwords to the new secret.

## Reading staging email

Console → Cloud Storage → `<project>-thapsus-stg-uk-mail`, or:

```sh
gcloud storage ls gs://<project>-thapsus-stg-uk-mail/
gcloud storage cat gs://<project>-thapsus-stg-uk-mail/<object>
```

## Cost

About £35–45 a month at light use (`docs/COSTS.md` → Google Cloud staging). Most of it is the Cloud SQL instance, which runs all the time. Set `app_min_instances = 1` to avoid cold starts, which adds about £12 a month.

## Tearing down

Ask the owner first (CLAUDE.md: deleting cloud resources or data).

1. Set `deletion_protection = false`.
2. Apply that change through the workflow.
3. Run `tofu destroy` with the same backend configuration.

Destroyed KMS key versions can still be restored for 30 days. The bootstrap resources (state bucket, image repository, deploy account, identity pool) are removed by hand, or by deleting the project.
